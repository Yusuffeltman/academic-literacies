**Statement Template Structure (in profile JSON-LD):**

Each template entry in the `templates` array follows the xAPI Profile spec:
```json
{
  "id": "https://w3id.org/xapi/aclit/v1/templates/{template-name}",
  "type": "StatementTemplate",
  "inScheme": "https://w3id.org/xapi/aclit/v1",
  "prefLabel": {"en": "Human Readable Name"},
  "definition": {"en": "When this statement is generated."},
  "verb": "{verb-iri}",
  "objectActivityType": "{activity-type-iri}",
  "contextGroupingActivityType": ["https://w3id.org/xapi/aclit/v1/activity-types/session"],
  "contextCategoryActivityType": ["https://w3id.org/xapi/aclit/v1"],
  "rules": [
    {
      "location": "$.context.contextActivities.grouping[*].id",
      "presence": "included"
    }
  ]
}
```

**Context pattern rules (apply to ALL templates except session-open):**
- `contextGroupingActivityType` includes session
- `contextCategoryActivityType` includes the profile
- Rule: `$.context.contextActivities.grouping` presence "included"
- Rule: `$.context.contextActivities.category` presence "included"

**Session-open template is special:**
- Does NOT reference session in grouping (it IS the session)
- Instead, grouping references course and module
- Includes device-type and connection-type context extensions as "included" rules

**JSON Schema files:**

Create xapi-profile/schemas/ directory. For each of the 22 templates, create a JSON Schema file named `{template-name}.schema.json` (e.g., `session-open.schema.json`).

Each schema validates the complete xAPI statement structure for that event type:
- `$schema`: `"https://json-schema.org/draft/2020-12/schema"`
- `title`: matches template prefLabel
- `description`: matches template definition
- `type`: `"object"`
- `required`: `["actor", "verb", "object", "timestamp"]` (minimum)
- Properties for actor (account structure), verb (fixed id), object (fixed type), context (contextActivities structure), result (required extensions)
- Additional required fields per template (e.g., writing-submitted requires result.extensions.word-count)

Keep schemas focused on validation constraints -- they should catch missing required fields and wrong types, not re-document the full xAPI spec. Use `$ref` or `$defs` for shared patterns (actor pattern, context pattern) within each file to avoid duplication.

Group similar templates: quiz-attempted/completed/passed/failed share most of the schema structure -- define a base quiz schema pattern and extend it. Same for help-seeking events.
